  - `driveChipTitle`: first line ``Drives {n} worktree{s}:`` then one line per driven worktree

## Attention model

### `src/lib/attention.ts`

```ts
/** The facts of a session's drive that decide whether it needs the human. */
export interface DriveFacts { drivenBy: string | null; brokered: boolean }
export function driveFacts(s: WorktreeSession | undefined): DriveFacts | undefined; // undefined when not driven

export function needsInput(state: SessionState, idleFromTurn: boolean, drive?: DriveFacts): boolean {
  if (drive?.drivenBy) {
    if (state === "waiting" && drive.brokered) return false; // the driver is deciding
    if (state === "idle") return false;                       // the driver reads the turn via `wait`
  }
  return state === "waiting" || (state === "idle" && idleFromTurn);
}
export function classifyAttention(state, idleFromTurn, drive?: DriveFacts): AttentionKind | null {
  if (!needsInput(state, idleFromTurn, drive)) return null; // invariant kept: non-null iff needsInput
  return state === "waiting" ? "waiting" : "finished";
}
```

`useAttention` passes `driveFacts(s)` at **every** call site: `updateBadge` (`needsInput`), the seed path,
the first-seen path and the transition loop (`before` uses the **previous** facts, so keep a
`prevDriveRef: Map<string, DriveFacts | undefined>` next to `prevRef`, updated beside it, pruned and reset
exactly like `prevRef`/`latchRef`; `now` uses the current facts). The latch itself is unchanged
(`latchIdleFromTurn`), so the rising edge fires correctly when the driver escalates (`before` false
because brokered, `now` true because no longer brokered) and when a drive is released.

`fire()` body: when `session.driven_by && session.escalated_reason && session.state === "waiting"` the
body is ``{driven_by} escalated: {reason}`` (reason cut at 140 chars with `…`); otherwise the existing
task-title/`needs attention` logic. Same body for the in-app banner and `notifySession`.

Result per case (this is the contract the tests assert):

| session | needsInput | kind | dock badge | toast |
|---|---|---|---|---|
| not driven, waiting | true | waiting | yes | yes |
| driven, waiting, `brokered` | false | none | no | no |
| driven, waiting, not brokered (escalated, or paused) | true | waiting | yes | yes, "alpha escalated: reason" when a reason exists |
| driven, idle after a turn (latched) | false | none | no | no |
| driven, busy / offline | false | none | no | no |
| not driven, idle after a turn | true | finished | yes | yes (unchanged) |

Releasing a drive while the worktree sits latched-idle produces one `finished` banner (the turn was never
read by a human); this is accepted (decision 6).

### `src-tauri/src/bg_notifier.rs` (port; change both sides and their tests together)

```rust
fn needs_input(state: &str, idle_from_turn: bool, driven: bool, brokered: bool) -> bool {
    if driven {
        if state == "waiting" && brokered { return false; }
        if state == "idle" { return false; }
    }
    state == "waiting" || (state == "idle" && idle_from_turn)
}
fn step_session(prev, next_state, active, driven: bool, brokered: bool) -> (..., bool)
```

`step_session` passes `driven`/`brokered` into `needs_input`; the stored tuple stays
`(prev_state, latch, prev_needs_input)` (`prev_needs_input` already stores the previous **result**, so no
extra state is needed). The caller reads `session.driven_by.is_some()` and `session.brokered`. The toast
body: when `driven_by` and `escalated_reason` are both `Some` and `state == "waiting"`: ``{driven_by}
escalated: {reason}`` (reason truncated to 140 chars on a char boundary plus `…`), else the existing
task title. Note the watcher's heartbeat skip uses `session_revision`, which 04 extends so a brokered ->
escalated flip is not skipped.

## State to visual mapping

Rows are the lane's effective state. `block` is the `.wt-block` / `.rail-dot` class; `badge` is the head-row
`.lane-drive-badge` (driven lanes only). "stalled" has no distinct state in v1 (a stalled worktree is a
`busy` session; `wait`'s `stalled` event is a CLI-only signal, overview risk 4), so its row is `busy`.

| state | not driven | driven by alpha |
|---|---|---|
| idle | block `idle` (green), steady | block `idle`; badge `⇠ alpha` (`driven`); no attention even after a turn |
| busy / stalled | block `busy` (amber); work dot | block `busy`; badge `driven`; work dot |
| waiting, human decides | block `waiting` (blue), glow + pulse (pulse off on the selected lane or reduced motion), group ring, toast | n/a (a driven session's waiting is one of the next two) |
| waiting, **brokered** | n/a | block `brokered` (blue tint, dashed outline, **no glow, no pulse**), badge `⇠ alpha · 1` (`deciding`, dashed), no ring, no toast, no badge |
| waiting, **escalated** (incl. timeout, take over, paused) | n/a | block `waiting` (glow + pulse), badge `⇠ alpha` (`escalated`, solid waiting colour) with the reason in its title, group ring, toast "alpha escalated: reason" |
| paused (any state above) | n/a | badge gains ` · paused` and the `paused` class (dotted outline, 75% opacity) |
| offline / terminated | block `offline` / `terminated` (45% opacity) | same block; badge `driven`, title as for `driven` |
| driver (drives 2) | normal block for its own state | n/a (one level: a driven lane is never a driver) |

Driver lane: head-row chip `drives 2` (`.lane-drive-chip`); the lane's own block colour follows its own
state.

## Singletonize decisions

1. **Quiet logic is one rule in two languages**, driven by `driven_by` + `brokered` on the session row,
   with the same truth table asserted in both test suites.
2. **No new theme token.** The brokered/driven styles reuse `--waiting`, `--accent-2`, `--proj`, `--bg-2`,
   `--tx-*`, `--line`, which already carry light/dark values; contrast is verified in the harness.
3. **Drive actions bypass `onLaneAction`** and call the DB-only commands with the lane's resolved project
   name, because driving works across projects and must never switch the human's active project.
4. **Banner is an overlay, not an in-flow strip,** so it cannot change the terminal's fitted size or send a
   resize to the pty; it hides the top terminal row while shown, an accepted cost of the warning. It is
   not dismissible (the warning is the point).
5. **The steal note (`forced_from`) shows in the pane banner only**, from `drives_list` for the active
   project, not on the rail: surfacing it on every lane would need a fifth activity field.
6. **Release while latched-idle fires one `finished` banner** (the turn was never read by a human); not
   special-cased.
7. **"Stalled" has no visual in v1** (renders as `busy`); `wait`'s `stalled` event is CLI-only.
8. **Group header ring ignores brokered lanes** (`waiting` counts only `blockState === "waiting"`); the
   header shows `N driven` instead.
9. **Overview (non-active) groups get the quiet rule too** via `isQuietWaiting`, since their session rows
   come from the same `sessions_list` fill (04); their toasts come from the Rust port.
10. **`useDrives` refetches only for the active project**, on `sessions://changed`; other warm projects'
    panes are hidden, so they use the activity-only fields.
11. **Take over has no confirm and Release has no confirm**; both are reversible (a re-`drive` binds again,
    a take over only escalates the currently pending prompts).
12. **Resume appears in the banner only while paused**; Pause itself lives only in the lane menu.
13. **`drive_paused` is read from activity** (an addition to 04's fields) so the menu label is right for
    any project; the banner and badge use the same field.
14. **Harness edits are local-only** and described, not committed.
