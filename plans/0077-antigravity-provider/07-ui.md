## Design

### `ProviderGlyph`

`GLYPHS: Record<CliKind, { label: string; path: string }>` replaces the ternaries:
`claude: { label: "Claude", path: CLAUDE_PATH }`, `codex: { label: "Codex", path: OPENAI_PATH }`,
`antigravity: { label: "Antigravity", path: ANTIGRAVITY_PATH }`. The component renders
`const { label, path } = GLYPHS[cli]` with the same `<span className="lane-cli-glyph" title={label}
aria-label={label}>` and `<svg width={SIZE} height={SIZE} viewBox="0 0 24 24" fill="currentColor"
aria-hidden="true"><path d={path} /></svg>` markup (single colour, `currentColor`, `viewBox="0 0 24 24"` like the
existing two). Update the file header comment to mention three marks.

`ANTIGRAVITY_PATH` source, in this order:

1. If the Simple Icons set (the source of the two existing marks, CC0 icon files) has an Antigravity icon, use
   its single `<path d="…">` verbatim and record `// Simple Icons "<slug>", <version>` above the constant. The
   package is not installed in this repo, so fetch the file with `curl` from the pinned npm package on
   `cdn.jsdelivr.net` (for example `…/npm/simple-icons@<pinned version>/icons/antigravity.svg`; the slug is
   unverified) and check that it contains exactly one `<path`.
2. Otherwise use this simplified single-path placeholder and record
   `// Simplified hand-drawn mark; no Simple Icons mark was available` above it:
   `M12 2 2 22h4.2L12 9.5 17.8 22H22L12 2Z` (README Open issue 6 asks the user to supply the real mark).

### Default-agent picker

`SettingsDrawer.tsx:906-919`: replace the two hard-coded buttons with
`{CLI_KINDS.map((cli) => <button key={cli} className={defaultCli === cli ? btnPrimary : btnGhost}
aria-pressed={defaultCli === cli} disabled={!snap.user.available[cli]} title={snap.user.available[cli] ?
undefined : `${cliTitle(cli)} not found`} onClick={() => setDefaultCli(cli)}>{cliTitle(cli)}</button>)}`. An
unavailable provider is shown but disabled with a "not found" title; the currently selected `defaultCli` stays
pressed even if it is unavailable (it is not auto-changed).

### `ProviderSettingsGroup` (new, `src/components/ProviderSettingsGroup.tsx`)

One component renders the Claude, Codex and Antigravity sections, replacing the duplicated blocks at
`SettingsDrawer.tsx:1020-1196`. Props (exact):

```ts
export interface ProviderForm { userPath: string; projPath: string; steps: string[]; autonomy: boolean }
export type DispatchEditorRender = (steps: string[], onChange: (steps: string[]) => void) => ReactNode;
export function ProviderSettingsGroup(props: {
  cli: CliKind;
  available: boolean;                    // snap.user.available[cli]
  hasCommittedFile: boolean;             // snap.project.has_committed_file
  projectAutonomy: boolean;              // snap.project.providers[cli].autonomy
  form: ProviderForm;
  onChange: (patch: Partial<ProviderForm>) => void;
  onToggleAutonomy: () => void;
  dispatchEditor?: DispatchEditorRender; // the render prop for this provider
}): JSX.Element;
```

and a `const PROVIDER_COPY: Record<CliKind, {…}>` holding the per-provider strings (so a missing provider is a
type error):

| | claude | codex | antigravity |
|---|---|---|---|
| autonomy button label | `Skip permission prompts` | `Bypass approvals & sandbox (danger)` | `Auto-approve tool permissions (danger)` |
| flag | `--dangerously-skip-permissions` | `--dangerously-bypass-approvals-and-sandbox` | `--dangerously-skip-permissions` |
| warning sentence | `Launches Claude with <flag>, bypassing its per-action approval prompts. Only enable if you understand the risk.` | `Launches Codex with <flag>, bypassing both its sandbox and its per-action approval prompts — broader than Claude's flag. Only enable if you understand the risk.` | `Launches Antigravity with <flag>, auto-approving every tool permission request. Only enable if you understand the risk.` |
| project-forces-autonomy note | `This project's keitora.toml enables skip-permissions, so its sessions launch with the flag regardless of the toggle above.` | `This project's keitora.toml enables Codex autonomy, so its sessions launch with the flag regardless of the toggle above.` | `This project's keitora.toml enables Antigravity autonomy, so its sessions launch with the flag regardless of the toggle above.` |
| not-found note | `Claude not found on PATH — install it, then reopen Settings.` | `Codex not found on PATH — install it, then reopen Settings.` | `Antigravity not found — install it, then reopen Settings.` |

(`<flag>` is rendered in a `<code>` element.) Markup per group, identical to the existing blocks: `<section
className="flex flex-col gap-3 border-t border-line pt-6">` with the title `cliTitle(cli)`; the not-found note
when `!available`; labels `` `${cliTitle(cli)} path (user default)` `` and `` `${cliTitle(cli)} path (project
override)` ``; the dispatch-ritual block; the autonomy row; the warning; the project-forces note when
`projectAutonomy`. It must keep these current behaviours:

- The "not found" note when `!available`. Claude now gets this too (today only Codex does). Path inputs (user and
  project) stay enabled for every provider regardless of availability, so a user can type a path to fix "not
  found" (README Open issue 9 resolution). Only the autonomy button (`disabled={!available}`) and the dispatch
  editor are disabled: the editor renders only when `dispatchEditor && available`, else the "Using Keitora's
  built-in dispatch prompt." / "`N` step(s) configured." text.
- The project path override is disabled without `hasCommittedFile` only (availability does not disable it); when
  `!hasCommittedFile` the note reads `A project-level {Title} override requires
  a committed <code>keitora.toml</code>. Commit a file below, or set the user-level default above.`
- Autonomy is saved immediately via `setSkipPermissions(cli, next)` outside the Save buttons (`onToggleAutonomy`
  is the drawer's `toggleAutonomy(cli)`).

### `SettingsDrawer` state and wiring

- Props: delete `codexDispatchEditor`; `dispatchEditor` becomes `dispatchEditors?: Partial<Record<CliKind,
  DispatchEditorRender>>`. `App.tsx:1263-1274` passes `dispatchEditors={{ claude: render, codex: render,
  antigravity: render }}` where `render = (steps, onChange) => <DispatchStepsEditor steps={steps}
  onChange={onChange} />` (one shared function; also pass `onOpenChange={(o) => { setSettingsOpen(o); if (!o)
  refreshAvailability(); }}`, doc 03).
- State is keyed by `CliKind`, not `projClaude`/`projCodex`/…: replace the ten state hooks at `:473-498` for
  paths, steps and autonomy with
  `const [forms, setForms] = useState<Record<CliKind, ProviderForm>>(emptyForms)` where
  `emptyForms = Object.fromEntries(CLI_KINDS.map((c) => [c, {userPath: "", projPath: "", steps: [], autonomy:
  false}]))`, and `const patchForm = (cli, patch) => setForms((f) => ({ ...f, [cli]: { ...f[cli], ...patch } }))`.
  `defaultCli`, `skipRestart`, `diffBase*`, `worktreesDir`, `archiveDays`, `logRetentionDays` stay separate.
  `skipRestart` stays shared and unseeded.
- The project and user sections seed separately, using functional updates so `refresh({project|user})` does not
  discard the other section's unsaved edits: `seedProject` patches only `projPath` (from
  `s.project.providers[cli].path ?? ""`) and `steps` (from `…dispatch_steps`) for every `cli in CLI_KINDS`;
  `seedUser` patches only `userPath` (`s.user.providers[cli].path ?? ""`) and `autonomy`
  (`s.user.providers[cli].autonomy`), plus `defaultCli`, `confirmRemove`, `skipRestart=false` as today.
- `saveProject` sends `providers: Object.fromEntries(CLI_KINDS.map((c) => [c, {path: nz(forms[c].projPath),
  dispatchSteps: forms[c].steps.map((s) => s.trim()).filter((s) => s !== "")}]))`; `saveUser` sends
  `providers: Object.fromEntries(CLI_KINDS.map((c) => [c, nz(forms[c].userPath)]))` and `defaultCli`.
- `toggleAutonomy(cli)` (`:644-662`) becomes: `const current = forms[cli].autonomy; const seeded =
  snap?.user.providers[cli].autonomy ?? false; const next = !current; await setSkipPermissions(cli, next);
  patchForm(cli, {autonomy: next}); setSkipRestart(next !== seeded);` (the `cli === "claude" ? … : …`
  branches go away).
- The three groups render as `CLI_KINDS.map((cli) => <ProviderSettingsGroup key={cli} cli={cli} available={
  snap.user.available[cli]} hasCommittedFile={snap.project.has_committed_file} projectAutonomy={
  snap.project.providers[cli].autonomy} form={forms[cli]} onChange={(p) => patchForm(cli, p)}
  onToggleAutonomy={() => void toggleAutonomy(cli)} dispatchEditor={dispatchEditors?.[cli]} />)` in place of the
  two blocks, keeping the shared restart prompt after them.
- The "agent cli updates" list (`:383-410`) iterates `CLI_KINDS`, reads `snapshot?.agents[cli] ?? null` (doc 05)
  and prints `cliTitle(cli)` instead of the raw `{cli}` (`:385`).
- `.harness/app.tsx:271-289`: replace the old flat fields with the keyed shapes: `project.providers = {claude:
  {path: null, autonomy: false, dispatch_steps: ["/clear", "/workflow {task_number}"]}, codex: {path: null,
  autonomy: false, dispatch_steps: []}, antigravity: {path: null, autonomy: false, dispatch_steps: []}}`,
  `user.providers = {claude: {path: null, autonomy: false}, codex: {…}, antigravity: {…}}`,
  `user.available = {claude: true, codex: false, antigravity: true}`; and wherever the harness returns an agent
  updates snapshot (none today) use `{agents: {claude: …, codex: …, antigravity: …}, …}`. Keep it working for UI
  screenshots (this file is git-ignored; do not commit it).
